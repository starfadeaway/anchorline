## 1. 差在哪（痛点）

| # | 痛点 | 具体表现 | 影响 |
|---|---|---|---|
| 1 | **评测规模与统计强度不足** | 154/168 都只跑 1 次/题；无配对 t 检验（用置换检验）；无 CI 自动跑分 | 结论只能写"方向性"，差异 1pp 以内不可信 |
| 2 | **记忆层与知识库的定位未说清** | Anchorline 是"事实记忆"，LoreKeeper 是"chunk 检索"；桥接实验显示融合无增益 | 用户会误以为二者可互相替代 |
| 3 | **页面冗余** | `/compare` 与评测页"臂对比"重复；`/traces` 与评测页 Trace tab、聊天页 Trace 面板三处重复；`/sessions` 与聊天页会话列表重复；报告页与记忆/会话页导出按钮重复 | 信息架构臃肿，维护三份逻辑 |
| 4 | **检索质量在页面级口径下无提升** | LoreKeeper 桥接：纯向量 = RRF = 0.8542 Recall@1；rerank 反而把 gold 挤掉 | 无法声称"检索组件更强" |
| 5 | **标注收尾未完成** | V1 自重复 16 题（48h 盲标）刚生成包，尚未标注 | 标注一致性无数据 |
| 6 | **可观测性弱** | 监控页只有静态统计；无请求延迟分布/错误率/超时率 | 出问题不好定位 |
| 7 | **聊天等待体验** | 模型调用最坏 240s，无流式 token、无"处理中"进度 | 用户以为卡死 |
| 8 | **部署未做** | Docker Compose 未写（按用户要求最后做） | 换机器要手工装 |

## 2. 冗余功能（建议合并/删除）

- **`/compare` 页面**：与评测页「臂对比」Tab 完全重复 → 删除页面，保留 Tab。
- **`/traces` 页面**：与评测页「Trace 浏览」Tab 重复 → 二选一（保留评测页 Tab，或把 Trace 做成独立页并把 Tab 去掉）。
- **`/sessions` 页面**：与聊天页左侧会话列表重叠 → 可合并为聊天页的"管理"入口（删除/导出）。
- **报告页导出**：与会话页/记忆页的导出按钮重复 → 报告页保留"全量导出"，其余页面只保留"当前视图导出"。

## 3. 缺的功能

| 优先级 | 缺失 | 说明 |
|---|---|---|
| P0 | 页面级重排 | 先把 chunk 聚合成页面，再对页面 rerank（桥接实验的直接改进） |
| P0 | 评测 CI | 每次改动自动跑 154 题回归，防止悄悄退化 |
| P1 | chunk 级 gold | LoreKeeper 只标到页面；chunk 级才能公平评估 rerank |
| P1 | 延迟/错误率监控 | 请求耗时分布、模型超时率、429 率 |
| P2 | SSE token 流 | 当前只有 tool/final 事件 |
| P2 | Docker Compose | 用户要求最后做 |
| P2 | 前端 e2e 接入 CI | 需要 MySQL+API，成本高（当前本地跑） |

## 4. 修改方向（按收益排序）

1. **页面级重排实验**：在 LoreKeeper 上验证「页面聚合 → rerank」是否恢复增益；这是唯一有机制解释、数据现成的改进。
2. **合并冗余页面**：把 8 个菜单项压到 6 个（聊天 / 记忆 / 评测[对比+Trace+桥接] / 审核 / 报告 / 设置），删除 `/compare`、`/traces` 独立页。
3. **评测 CI**：GitHub Actions 里加一个 job（需要 MySQL 容器 + provider key 用 secrets），跑 154 题并 artifact 化结果。
4. **监控真实指标**：加中间件记录每请求耗时/状态，`/monitor` 改成真实延迟分位数。
5. **SSE token 流**：聊天页逐 token 显示，降低"卡死"感。

## 5. 三个提升方向里最推荐哪个

**页面级重排**。

理由：
- **有机制解释**：桥接实验的负结果（rerank 把页面级 gold 挤掉）正好指向"chunk 相关性 ≠ 页面相关性"；页面级重排直接修复这个错位。
- **数据现成**：LoreKeeper 的 48 条 gold_pages 与 chunk→page 映射已就绪，不需要重新标注。
- **可复现**：同一脚本加一条聚合规则即可对比（chunk top-k → 按 page 聚合 max score → rerank 页面级文本）。
- 另外两个方向：chunk 级 gold 需要 LoreKeeper 重新标注（成本高、周期长），换向量口径只是"对照"不构成提升。

预期：如果页面级重排仍无增益，说明"在强向量基线上融合无空间"，这个负结果同样有价值，且能写进报告。
