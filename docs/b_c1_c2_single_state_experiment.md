# B/C1/C2 索引改「单 state」实验（§42.1 / §42.2 的真修法）

> 日期：2026-11-12
> 背景：评审 42.1 指出 B/C1 与 D 的**检索单元粒度不一致**——B/C1 是 3-state 拼接
> （median 49,341 / 39,998 字符），D 是单 state（median 702）。4k 预算下 B/C1 的 top-6
> 没有一条能完整入预算（必然 top-1 拦腰截断 + 5 条丢弃），而 D 的 92.7% 装得下。
> 42.2 进一步指出：保头截断保住的是**最旧的 state**，center（答案通常所在）在 27%–50% 处。
>
> 本实验把 B/C1/C2 索引切成**单 state**（每 state 一条，检索单元 = center state 本身），
> 保持 4k 预算 / top-6 / 同一批 154 题不变。C2 与 B 共用 `v2_web_slices`，所以 B 重建后
> C2 必须一起重跑；D 索引本来就是单 state，不受影响。

## 设置

| 项 | 值 |
|---|---|
| 索引重建 | `build_baseline_index.py --radius 0`、`build_c1_arm_index.py --radius 0` |
| 行数 | B / C1 各 1737 条（与旧索引同规模） |
| 切片长度 | B：min 89 / median 15,998 / max 15,998（cap 16000）；C1：median 16,603 / max 40,000 |
| 题目 | 154（确定性 web 题，seed=42） |
| reader / 预算 | deepseek-flash / temperature 1.0 / 4k tokens / top-6 |
| 产物 | `data/eval/_drafts/{b,c1,c2}_arm_154_radius0.json` |

## 结果（新旧对比）

| 臂 | 旧（3-state，保头截断） | 新（单 state） | 配对差 | 精确 p | 变化题数 |
|---|---|---|---|---|---|
| **B** | 57.14%（88/154） | **60.39%（93/154）** | **+3.25pp** | 0.4996 | 35（20 好 / 15 差） |
| **C1** | 53.90%（83/154） | **57.14%（88/154）** | **+3.25pp** | 0.4996 | 35（20 好 / 15 差） |
| **C2** | 57.14%（88/154） | 57.14%（88/154） | +0.00pp | 1.0000 | 36（净 0） |
| **D**（未变） | 66.23%（102/154） | 66.23% | — | — | — |

B/C1 的 +3.25pp 来自**同一批 center 题**（35 题、方向完全一致）——旧索引注入的是
「3 个 state 拼接后保头截断」= center−1（最旧），center 自己的 AXTree 被切掉；单 state
后注入的恰好是 center。C2 净值不变（36 题变化互相抵消），说明修复对 a11y-only + L0 去重
的组合影响方向不定。

## 单 state 口径下的 2×2（154 题）

| 对比 | 差值 | 精确 p | 旧口径（3-state） | 旧 p |
|---|---|---|---|---|
| B -> C1 | −3.25pp | 0.5224 | −3.25pp | 0.4869 |
| C2 -> D | +9.09pp | 0.0488 | +9.09pp | 0.0336 |
| B -> C2 | −3.25pp | 0.4049 | 0.00pp | 1.0000 |
| C1 -> D | +9.09pp | 0.0201 | +12.34pp | 0.0066 |
| B -> D | **+5.84pp** | **0.2327** | +9.09pp | 0.0385 |
| C1 -> D_neighbor | +7.14pp | 0.1263 | +10.39pp | 0.0195 |
| D -> D_neighbor | −1.95pp | 0.7359 | −1.95pp | 0.7359 |

**结论变化（重要）**：

1. **`B -> D` 不再显著**（p=0.2327，旧 p=0.0385）——B 的索引缺陷被修复后，B 从 57.14%
   升到 60.39%，D 的优势缩小到 5.84pp 且不显著。旧报告「D 是唯一显著优于 B 的臂」在
   单 state 口径下**不再成立**。
2. `C1 -> D` 仍显著（+9.09pp，p=0.0201），但 `C1 -> D_neighbor`（单变量压缩格）不再显著
   （p=0.1263）——旧口径下「压缩在完整轨迹下有效约 +10pp」需要改写成"约 +7pp，不显著"。
3. 方向性结论大体保留：完整轨迹侧（C2→D、C1→D）仍有正收益；a11y-only 侧（B→C2）无显著差。

## 决定

- **不覆盖已入库产物**：新产物在 `_drafts/`；旧报告数字保持原样（历史口径可复现）。
- 报告口径是否切换到单 state，需要项目 owner 明确决定，因为：
  - 它会让 `B -> D` 的显著性结论反转（这是"有理由的改"——旧 2×2 的同预算前提不成立）；
  - 168 口径、m3_summary、reported_numbers 都需要同步。
- **不要再动字符上限**（2666 已被证伪）。
